# Generative-AI task exposure — scoring protocol

Operating procedure for producing a defensible exposure score. Read
[`methodology.md`](methodology.md) §5 first for what the measure is;
this document is how to run it.

---

## The standing statement

> Generative-AI task exposure indicates how much an occupation's tasks may be
> affected or assisted by generative AI. It is not an estimate of automation,
> displacement, layoffs, or future employment.

It is displayed beside the exposure layer, not in a collapsible section, and it
belongs in any report that quotes a score.

---

## Preconditions

A run is legitimate only if all of these hold. The harness enforces the first
four and refuses otherwise.

1. **Task evidence exists.** A task file with `task_id`, `task_statement`,
   `occupation_title`, `occupation_source`, `psoc_code`,
   `crosswalk_match_type`, `crosswalk_match_quality`, `task_importance`.
   Scoring titles instead is the v1 defect; `load_tasks` raises rather than
   degrade to it.
2. **At least two replicates.** `--runs 1` is refused: a single sample cannot
   report its own stability.
3. **The prompt states no target distribution.** `assert_prompt_is_unanchored`
   scans for expected-average instructions and refuses.
4. **No labour-market inputs.** `assert_no_prohibited_inputs` refuses to send
   employment, wages, OFW share or informality to the model.
5. A crosswalk from PSOC to the task source, with recorded match type and
   quality.

## Running

```bash
export OPENROUTER_API_KEY=...          # never committed
make score-exposure MODEL=<provider/model-id> RUNS=5
make sensitivity
```

Each invocation writes a new directory under `data/exposure/runs/<run_id>/`
containing `run.json` and every raw response under `raw/`. **Reruns never
overwrite history.**

## What each run records

`run_id` · `scoring_date` · `model_provider` · `model_id` ·
`model_release_or_snapshot` · `temperature` · `run_count` · `seed` ·
`rubric_version` · `prompt_version` · prompt and rubric file paths ·
`task_source` · `task_count` · `aggregation_method` · `human_review_status` ·
`independent_expert_validation` · per-task replicate scores with raw-response
references.

## Aggregation

**Across replicates:** median, with min, max, range and standard deviation
retained. A task whose replicates span more than one point is marked
`unstable`. Disagreement is published, not smoothed.

**Across tasks:** unweighted mean and importance-weighted mean, computed
separately and published side by side. Neither is *the* score. They are never
averaged together.

**Across dimensions:** nothing. A, B, C and D are never combined. A weighted sum
of them would read as a job-loss probability.

---

## Release gates

A score reaches the release only if all hold:

| Gate | Threshold |
| --- | --- |
| Replicates | ≥ 2, and ≥ 3 recommended |
| Task-level stability | A task with replicate range > 1 is marked unstable |
| Occupation-level stability | > 25% unstable tasks → publish the range, not a point score |
| Crosswalk quality | `low` quality tasks are suppressed, not averaged in |
| Evidence confidence | Dimension D ≤ 1 → publish the score as title-derived and unreliable, or suppress |
| Provenance | All 11 provenance fields present; validated by `check_model_scores` |
| Face validity | Watchlist reviewed; outcome recorded in `human_review_status` |

## Validation battery

Specified in [`sensitivity-report.md`](sensitivity-report.md), regenerated by
`make sensitivity`.

1. **Face validity** — manual review of the highest and lowest scoring
   occupations, plus a standing watchlist of physical, high-touch, mixed and
   Philippine-specific work.
2. **Prompt-wording sensitivity** — re-run under a variant prompt at the same
   rubric version. A dimension that moves materially on paraphrase is reported
   as prompt-sensitive.
3. **Repeat-run stability** — within-model, as above.
4. **Cross-model comparison** — mean absolute difference and exact-agreement
   share. Disagreement is published, not resolved by picking a favourite.
5. **Task-weighting sensitivity** — unweighted vs importance-weighted.
6. **Crosswalk-quality sensitivity** — mean score by match quality. A
   systematic gradient means the measure is partly reporting mapping quality
   rather than task content, and the low band is suppressed.
7. **Comparison with an established task-exposure methodology**, where
   licensing permits. Reported as concordance, never as validation.
8. **Error analysis** for Philippine-specific occupations, physical and
   high-touch occupations, and mixed occupations.

## Human review

`human_review_status` starts at `not_reviewed`. A reviewer sets it after
examining the watchlist and recording what they changed and why.

**Do not claim external expert validation unless a real, named or documented
external review occurred.** Absent that, the release carries:

> This experimental score has not yet undergone independent labour-economist
> validation.

A model's rationale is not validation. It is an artifact of the same process
that produced the score. The interface frames it as "the scoring model judged",
never as a finding.

---

## Reporting a score responsibly

**Do** name the rubric and prompt version, the model, the run count and the
stability; report all four dimensions; state the crosswalk quality; carry the
standing statement.

**Do not** call it risk, automation probability, replacement probability or
displacement; do not convert it into a headcount or a peso figure; do not rank
occupations by "most exposed" without the stability and crosswalk quality
attached; do not compare scores across rubric or prompt versions.

### The BPO caution

Contact-centre and business-process work is the occupation most likely to be
reported on from this measure in a Philippine context, and the one where the
gap between task exposure and employment outcome is widest. A high dimension A
score there says a model can perform much of the task content. It does not say
what will happen to employment, which depends on client decisions, contract
structures, cost differentials, regulation, quality requirements, and work that
does not exist yet. Report it with that gap made explicit, or do not report it.
